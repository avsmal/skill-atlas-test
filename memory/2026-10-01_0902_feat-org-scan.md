# PR #20 — scan: scan every repository of a GitHub organization or user

- **Date/time:** 2026-10-01, discussion started ~08:50 UTC, PR opened 09:02 UTC
- **Branch:** `feat/org-scan`
- **PR:** https://github.com/avsmal/skill-atlas-test/pull/20

## What was asked
- An option to scan all repositories of a GitHub organization: if the URL is an organization's,
  scan all of its repositories.

## What was decided / built
- Detected from the URL shape (`https://github.com/<owner>`, `github.com/<owner>`,
  `https://github.com/orgs/<owner>`), not a separate flag, as the request described. A bare `<owner>`
  stays a (local) git argument, and `o/r` stays a single repo, so existing inputs keep their meaning.
- The repository list comes from the `GET /users/<owner>/repos` REST endpoint, which serves orgs and users alike
  (checked live). Stdlib `urllib` was used to avoid a dependency. `SKILL_ATLAS_GITHUB_API` overrides the
  base URL so tests can use a local fake.
- Forks are skipped by default (`--include-forks`), because their skills are the upstream's, in line with the
  spec's "project's own workflow" idea. Archived repos are kept.
- `--jobs` (default 4) runs `ThreadPoolExecutor.map`, which keeps output in name order. Storing happens on the
  main thread. Each repo is stored as it finishes, so an interrupted run keeps its progress.
- In text output, 0-skill repos are omitted: in real orgs most repos have none and would bury the results.
  They are still stored, so the catalogue lists them.
- A clone failure doesn't stop the run but sets exit 1. Empty repositories (found in a live `anthropics`
  run: `homebrew-claude`, "branch yet to be born") are detected after the clone (`EmptyRepoError`). In an org
  scan they are a warning, not a failure. A single scan says `error: repository is empty`.
- The web UI refuses owner URLs with a 400 pointing to the CLI, even with `--allow-local`, because one page
  load would clone hundreds of repos. Web org scans are listed under *Future work*.

## Context
- This sandbox's proxy blocks `files.pythonhosted.org`, so `pip install` fails, but GitHub is reachable.
  Tests ran from shallow GitHub clones of pytest, pluggy, iniconfig, packaging, pygments and pyyaml
  (pure Python) on `PYTHONPATH`, after hand-writing `_pytest/_version.py` and `pluggy/_version.py`.
  Pillow can't be installed that way, so `tests/test_demo_video.py` only runs on CI.
- Live numbers (2026-10-01): JetBrains has ~866 public repos; anthropics has 88 plus 25 forks, with 30 skills
  in 9 repos, and takes ~8 s with `--jobs 8`.
